# Suggested GitHub labels

Create these labels in the repository before using the issue forms. Labels communicate progress; they do not grant approval or bypass required checks.

| Label | Purpose |
| --- | --- |
| `idea` | New application proposal awaiting requirements work |
| `stage:idea` | Lifecycle state: idea submitted |
| `stage:requirements` | Requirements drafted or awaiting human scope approval |
| `stage:architecture` | Architecture and plan drafted or awaiting approval |
| `stage:implementation` | Approved implementation task in progress |
| `stage:review` | Pull request under independent review |
| `stage:release` | Release preparation and human approval |
| `task` | Bounded implementation task |
| `bug` | Reproducible defect |

Update issue labels only when the recorded artifacts and human decisions support the new state. Configure milestones per idea/release as appropriate; there is no fixed shared milestone name.
