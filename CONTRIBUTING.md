# Contributing

1. Open an idea or implementation-task issue using the provided templates. Preserve its stable ID (`IDEA-###` or `TASK-###`) in branches, commits, and pull requests.
2. Work on a focused branch and link the originating issue and acceptance criteria in the PR.
3. Add or update tests with behavior changes. Run both documented unittest commands and include their output in the PR.
4. Do not change approval rules to unblock a task. Human approval, CI, and independent review are separate gates.
5. Keep factory code and sample application code clearly separated. Avoid dependencies unless justified and reviewed.

See [the workflow](README.md#workflow) and [security guidance](SECURITY.md) for the full process.
